# 工作记录 · DSH 插件

独立存储的日报工作区，目标运行版本 **DSH 0.1.7-rc.2**，需要 Node.js ^22.19.0 或 >=24.0.0。界面入口需要 **@lemoncat7/dsh-knowledge >=2.12.0**，请同时安装两个插件。不依赖知识库挂载、伙伴或任务看板，不修改 DSH 源码。

## 使用

安装插件后从「知识库 → 工作记录 → 工作日报」进入；不在 DSH 全局侧栏增加独立按钮。知识库提供工作区导航，工作记录模块保留独立数据库和任务队列。在「采集设置」选择项目并启用采集；默认关闭，旧会话不会被追溯读取。项目按会话工作目录精确匹配。会话完成时保存本轮用户文本与最后一条助手结论，人工补记也可作为来源。

采集范围支持全部项目（包含未来项目）、选择当前/已记录项目以及手写项目路径。默认关闭采集，空项目选择不会被视作全部。

点击「整理日报」才调用模型，不在每轮对话增加模型请求。默认使用当天最后一条素材的会话模型，也可从 DSH 已配置模型列表选择，无需手填 provider/model。日报按项目组织进展、决定、交付与后续事项；模型被要求区分计划、声称完成与实际核验。日报仍应由用户核对，不等同于执行结果的独立验收。

正文中的「查看依据」可查看原始素材并打开来源会话；打开到会话，不保证滚动定位到该轮。来源记录可按项目和文本筛选、排除或重新纳入。已排除的内容不会参与下一次整理，现有日报不会被隐式改写。

支持选择日期、补记、编辑 Markdown、复制（含非 HTTPS 回退）、导出、历史版本作为编辑草稿。移动端日期从弹窗选择。沿用现有插件的冷灰半透明面板、磨砂正文与中性深色材质，不增加循环动画。

## 持久性与并发

- 数据统一存于服务端 `worklog/worklog.sqlite`，同一服务的不同客户端共享，不写入知识库。SQLite WAL 模式；备份应使用 SQLite 备份机制或停服务后一并复制数据库/WAL文件。
- 采集以会话 ID + 轮次去重。按配置时区归日，改变时区仅影响后续采集。
- 整理任务先持久化，再调用模型。同一天只允许一个活动任务；服务重启恢复运行中的任务。自动最多尝试三次，失败/取消可重新整理。
- 保存使用日报 revision 校验；生成期间人工编辑或排除来源，旧结果不得覆盖。新增来源保留为「待整理」。手工编辑的日报再次整理须明确确认，旧版保留历史。
- 客户端仅在工作区可见时每 6 秒检查轻量版本号；变化后加载数据，不另建长轮询连接。
- API 由 DSH 的登录认证保护，另校验客户端头、浏览器来源。官方 `dsh-app://app` 仅允许访问 loopback Host。远程访问插件/反向代理部署时还需验证 `/worklog-control/v1` 的认证转发，**不可匿名放行**。

## 第一版边界

每轮保存用户文本最多 16,000 字符、助手结论最多 32,000 字符，节选会明确标记。单次整理素材超过 180,000 字符时明确拒绝，不悄悄丢弃部分记录。当前不做历史聊天回填、跨设备独立服务同步、周报、自动渠道推送或附件副本搬运；交付路径来自原会话文本，文件访问仍由原插件负责。

启用采集意味着对话文本会复制到独立的工作记录库。关闭采集/排除来源不会删除历史数据；不要在包含敏感信息的项目开启。当前不是多租户隔离存储，适用 DSH 同一登录用户的工作区。

## 代码职责

| 模块 | 职责 |
| --- | --- |
| `domain.js` | 输入验证、日期、轮次快照与采集范围 |
| `store.js` | SQLite、去重、版本与持久任务 |
| `worker.js` | 串行整理、取消、重试、重启恢复 |
| `generator.js` | 有界模型请求、来源 ID 校验 |
| `http.js` | 请求来源检查、JSON API |
| `index.js` / `client.jsx` | Host 生命周期与工作区接入 |
| `ui/` | 请求、弹窗、设置、Markdown 与工作区 |

## 开发验证

```sh
npm ci
npm test
npm run build
npm pack --dry-run
# 安装 playwright-core 和浏览器后，或通过 PLAYWRIGHT_MODULE 指定已有模块：
node scripts/browser-smoke.mjs
```

单元/HTTP 测试验证采集范围、时区、去重、版本冲突、持久恢复、取消、自动重试、来源验证和浏览器/Desktop 来源安全。浏览器 fixture 使用真实插件 HTTP/SQLite，模型生成单元测试使用替身；正式 Host、真实模型和远程转发仍需部署验收。
